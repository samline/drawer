# Audit: `@samline/drawer` v2.0.8 → v3.0.0-beta.3

**Filed**: 2026-07-25
**Reporter**: easytrip project (Laravel 12, consumer of `@samline/drawer`)
**Status**: Reference document — not a bug report, but a working note that the consumer is keeping for itself. The package maintainer can use it as context for the 3.0.0 stable release.

---

## TL;DR

`@samline/drawer@3.0.0-beta.3` is a **major architectural change** from v2.0.8: it drops React/Vue/Svelte as peer dependencies and goes pure vanilla. The bundle drops by ~400KB, the package now has zero peer dependencies, and the CSS contract is mostly stable. But the package also changed the dialog mount lifecycle (overlay mounts at create time, not at open time) and introduced a couple of new "hidden" DOM nodes (`[data-drawer-title]`, `[data-drawer-description]`) that the consumer CSS wasn't expecting. There are 5 known bugs in beta.3 (3 closed, 2 open), most of them caused by the architectural change. The remaining issues are around modal-style drawers and the close-button flow.

This audit is for the consumer's own reference; it's not a request for the package to revert or branch. The consumer is happy with the direction, just wants the bugs fixed before going to stable.

---

## What improved (v2 → v3)

### 1. Bundle size

- v2.0.8: **2.47 MB** (includes React + Radix Dialog + Vaul drag pipeline as a side effect of using Vaul under the hood).
- v3.0.0-beta.3: **2.07 MB** — measured in the consumer's build.
- Saving: ~400KB, ~16% of the bundle. For the easytrip project specifically, this is significant because the rest of the bundle is the same; the only thing that changed is the drawer's runtime.

### 2. Peer dependencies

- v2.0.8: peer-deps on `react`, `react-dom`, `svelte`, `vue` (any one is required to use the package).
- v3.0.0-beta.3: **zero peer dependencies**. The package is fully self-contained.

### 3. Direct DOM manipulation

- v2.0.8: built on `@radix-ui/react-dialog` + Vaul for drag. The actual drawer DOM was rendered by React (the consumer's `createDrawer()` was a thin React wrapper).
- v3.0.0-beta.3: builds DOM directly. No React runtime, no virtual DOM. The consumer's `createDrawer()` returns a controller object with a `setOpen` method (instead of a React component).

### 4. Better API surface

- New helpers: `getDrawer`, `getDrawers`, `getParentDrawer`, `getChildDrawers`, `openDrawer`, `closeDrawer`, `toggleDrawer`, `updateDrawer`, `destroyDrawer`, `configureDrawer`, `createDrawerController`.
- Easier ID-based access: `closeDrawer(id)` is cleaner than maintaining a `window.Drawer.available[id]` map.
- New options: `onOpenChange`, `onClose`, `onAnimationEnd`, `onDragChange`, `onReleaseChange` — more granular than v2's single `onOpenChange`.

### 5. Better CSS contract

- v2: depended on Radix's `[data-state="open"|"closed"]` attributes for styling, but the animation classes (`data-state="open"`) didn't match the v2 CSS animations. The consumer had to override.
- v3: introduces explicit `data-drawer-vanilla-node` and `data-drawer-vanilla-body` slots that the consumer CSS can target reliably. The package re-introduced `data-drawer-vanilla-node` in 3.0.0-beta.2 (commit `efad4c0`) to fix a regression.

### 6. Drag pipeline (new feature)

- v2: Vaul-based drag (limited, opinionated).
- v3.0.0-beta.3: a 5-phase drag pipeline (Phases A-E), wired in commit `6c4ec4c`. More flexible, supports custom snap points, more event hooks.

### 7. Build & test infrastructure

- v2: `bunchee` + `esbuild` + `linkedom`, custom `scripts/build.mjs` and `scripts/sync-dist.mjs`.
- v3.0.0-beta.3: `tsup` + `vitest` + `jsdom` + `prettier 3`. Standard tooling that matches `@samline/forms` and `@samline/notify`.

## What regressed (v2 → v3)

### 1. **Drawer visible on page load** (Bug A, fixed in `3038ab4`)

- v2: the overlay was only mounted when the drawer was opened, so the page-load state was clean.
- v3.0.0-beta.3: the overlay is mounted at create time. The CSS `slideToX` / `fadeOut` keyframe animations end at the off-screen state, but without `animation-fill-mode: forwards` the element snaps back to its natural position. Result: every drawer was visible on page load.
- **Fix**: `3038ab4` added `animation-fill-mode: forwards` to the 5 closed-state rules.

### 2. **Memory leak: `mouseup` on overlay creates duplicate `[data-drawer]` wrappers** (Bug B, fixed in `346aec0`)

- v2: every `setOpen` was idempotent; the wrapper was reused.
- v3.0.0-beta: each `mouseup` on the overlay called `renderVanillaDrawer(id)` unconditionally, which ran `mountVanillaDialog` → `teardownMount`. The new mount created a new `[data-drawer]`, but the old one was not removed from the DOM (the `teardownMount` only removed `trigger` and `overlay`, not `content`).
- **Fix**: `346aec0` made `teardownMount` symmetric — it now also removes `state.content` from the DOM.

### 3. **Overlay with `data-state="closed"` captures clicks** (Bug C, fixed in the user's local workspace, not yet committed)

- v2: the overlay didn't exist on page load (only mounted on open), so this wasn't a problem.
- v3.0.0-beta.3: the overlay is mounted at create time with `data-state="closed"`, `opacity: 0` (after the `fadeOut` animation), but `pointer-events: auto` (default). At `z-index: 100` and `position: fixed; inset: 0`, it covers the entire viewport. Result: every click on the page is intercepted by the invisible overlay. The consumer's header (with `z-index: 10`) becomes unresponsive.
- **Fix**: the user added `pointer-events: none` to the `[data-drawer-overlay][data-state="closed"]` rule in `src/style.css`. This is in the consumer's local workspace but not yet committed to git (commit pending).

### 4. **Text leaks into modal drawers via `ariaLabel`** (Bug D, open)

- v2: this wasn't a problem because v2 didn't have the `ariaLabel` auto-promotion feature.
- v3.0.0-beta.3: the `ariaLabel` option is auto-promoted to the `[data-drawer-title]` slot when no `title` is provided. The slot has no default visual hiding. Consumers that use `ariaLabel` for accessibility (e.g. `ariaLabel: config('app.name')`) get the text visible at the top of the drawer.
- **Fix**: pending. The consumer's workaround is to add `titleVisuallyHidden: true` to every modal drawer's options.

### 5. **Modal drawer auto-opens on page load** (Bug E, open, not really a bug)

- v2: easytrip passed `open: true` in the drawer's options because in v2, the dialog had to be open at mount time to be visible.
- v3.0.0-beta.3: `open: true` means "the drawer is open at mount time, no animation". The consumer's pattern still works, but with Vite's HMR re-mounting, the modal flashes briefly.
- **Status**: working as designed. The consumer should use `setOpen(true)` after the drawer is mounted, or accept the auto-open. Not really a bug, just a behavior change.

### 6. **Close button doesn't work on modal drawers** (Bug F, open, hard to reproduce)

- v2: the consumer's close button worked.
- v3.0.0-beta.3: the consumer reports the close button does not work in the browser. Happy-dom tests show the listener fires correctly and `setOpen(false)` is called successfully.
- **Hypothesis**: Vite's HMR re-runs the consumer's `<script>` on every change, adding multiple `document.addEventListener('click', ...)` listeners. The new ones reference the new controller, but the old ones still fire and call `setOpen(false)` on a stale controller. The new controller may be the one that drives the visible drawer, but the click might be hitting an old DOM element with the same id.
- **Status**: open. The consumer's workaround is to switch from the manual `document.addEventListener` pattern to the package's `closeDrawer(id)` helper, called from an inline `onclick` attribute on the close button.

## What still needs improvement (consumer's wishlist for stable 3.0.0)

### 1. **Documentation**

The README, the VanillaDrawerOptions JSDoc, and the runtime options (especially `title`, `ariaLabel`, `open`, `dismissible`, `modal`) need clearer documentation about:

- The mount-time lifecycle (overlay mounts immediately, not at open).
- The title slot's role as an a11y target by default.
- The behavior of `ariaLabel` auto-promotion to the title slot.
- The close-button pattern (and the recommended way to wire it without HMR pitfalls).

### 2. **Built-in close button**

A `closeButton: true` option in `VanillaDrawerOptions` that renders a close button inside the drawer and wires it to the controller. Consumers wouldn't need to write a close-button listener at all. This is a small feature, ~10 lines of code in `mountVanillaDialog`, but it would eliminate the most common source of HMR-related bugs.

### 3. **Helper-based API promotion**

The package's README and examples should prefer the helper-based API (`openDrawer(id)`, `closeDrawer(id)`, `getDrawer(id)`) over the manual `window.Drawer.available[id]` pattern. The helper-based API is HMR-safe by design (it looks up the controller by id at call time, so it never holds a stale reference).

### 4. **Default styling**

The package's `style.css` provides animations but not positioning. Consumers need to set `position: fixed; top/right/bottom/left` themselves. This is by design (the package is style-agnostic), but a starter stylesheet or a "do this to get a working drawer" example would help new consumers.

### 5. **v3 stability**

The package is in `3.0.0-beta.3` as of this audit. For production use, the consumer is waiting for a stable `3.0.0` (or a `3.0.0-rc.1` with the bugs in this audit fixed). The consumer is testing the betas but is not ready to merge the upgrade to the main branch until the package is stable.
