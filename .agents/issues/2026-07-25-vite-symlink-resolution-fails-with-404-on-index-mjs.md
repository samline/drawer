# Bug: Vite 7 symlink dev-server resolver 404s on `dist/index.mjs`

**Filed**: 2026-07-25
**Reporter**: easytrip project (Laravel 12, consumer of `@samline/drawer`)
**Status**: ✅ **Closed** — fixed in v3.0.0-beta.3 by adding a one-line `export * from './index.js'` shim at `dist/index.mjs` from the tsup `onSuccess` hook in `tsup.config.ts`.
**Severity**: High (the entire consumer entry module fails to evaluate under Vite 7)
**Affected versions**: `@samline/drawer@3.0.0-beta.0` … `3.0.0-beta.2`
**Fixed in**: `tsup.config.ts` writes `dist/index.mjs` after the index build runs.

---

## TL;DR

Vite 7's symlink-aware dev-server resolver walks the filesystem instead of consulting the `exports` map in `package.json`. When the resolver hits a symlinked `node_modules/@samline/drawer`, it falls back to `dist/index.mjs`. The tsup build emits `dist/index.js` (matching the canonical ESM output and `package.json#exports.import`), not `dist/index.mjs`, so Vite gets a 404 and the entire consumer entry module fails to evaluate. Every other `@samline/*` global that depends on the drawer entry also fails to load.

The fix is a one-line `export * from './index.js'` shim at `dist/index.mjs`, written by the tsup `onSuccess` hook. The shim keeps the canonical ESM output name (no rename to `.mjs`) and adds a path Vite's symlink resolver can locate.

---

## Steps to reproduce

1. Install `@samline/drawer@3.0.0-beta.2` in any consumer that uses Vite 7.
2. Symlink the package into `node_modules` (e.g. `"@samline/drawer": "file:/path/to/drawer"` in `package.json`).
3. Run `vite dev`.
4. Open the browser console.

**Expected**: the consumer app loads, every `@samline/*` global initializes, the drawer is available via the package entry.
**Actual (pre-fix)**: the browser console reports a 404 on `dist/index.mjs`. The drawer entry module fails to evaluate. Every other `@samline/*` global that imports the drawer is also broken.

---

## Root cause

Vite 7's symlink-aware dev-server resolver uses an iterative filesystem walk to resolve module specifiers. When the resolver encounters a symlinked `node_modules/@samline/drawer`, it dereferences the symlink and looks for the entry module at the most likely path:

1. The `package.json#exports.import` field (modern Node + bundlers) — Vite's symlink resolver **does not** consult this; only the modern non-symlink resolver does.
2. The `package.json#module` field (legacy bundler convention) — Vite does check this, and the value points to `dist/index.js`.
3. A `dist/index.mjs` fallback (Vite's symlink heuristic) — Vite assumes the package was built with native `"type": "module"` semantics and prefers the `.mjs` extension.

The build emits `dist/index.js` (because tsup's `format: ['esm', 'cjs']` setting produces `index.js` for ESM and `index.cjs` for CJS, with `outExtension` left at its default). Vite's symlink resolver looks for `dist/index.mjs`, gets a 404, and bails.

The non-symlink resolver would have found `dist/index.js` via the `exports.import` field. The non-symlink path works fine; only the symlink path is broken.

## Fix

Add a one-line shim that the tsup `onSuccess` hook writes after the index build runs:

```ts
// tsup.config.ts
const copyStylesHook = async (): Promise<void> => {
  copyFileSync(resolve('src/style.css'), resolve('dist/style.css'))
  writeFileSync(
    resolve('dist/index.mjs'),
    "// Auto-generated by tsup's `onSuccess` hook. Re-exports the\n" +
      "// canonical ESM entry so Vite 7's symlink-aware dev-server\n" +
      '// resolver (which falls back to `dist/index.mjs` when it does\n' +
      '// not consult the `exports` map) can locate the entry. The\n' +
      "// canonical `dist/index.js` is what `package.json`'s\n" +
      '// `exports.import` and `module` fields point to; native Node\n' +
      '// `"type": "module"` consumers continue to use that path.\n' +
      "export * from './index.js'\n"
  )
}
```

Two design choices worth noting:

- **Option A (chosen)** — keep the canonical ESM output at `dist/index.js`, add a `dist/index.mjs` shim. Native Node consumers (`"type": "module"`) continue to resolve `dist/index.js` via `exports.import`. Vite's symlink resolver finds the shim.
- **Option B (rejected)** — rename the ESM output to `dist/index.mjs` (set `outExtension: { js: '.mjs' }`). This breaks native Node consumers that resolve `dist/index.js` via `exports.import` and would also require updating `package.json` to point at the new name. The renames cascade.

Option A is the smaller change and keeps the canonical name stable.

## Regression test

`test/vite-symlink-mjs-shim.test.ts` pins the fix:

1. The tsup `onSuccess` hook references `dist/index.mjs` and writes a re-export from `./index.js`.
2. After a build, `dist/index.mjs` exists and re-exports from `./index.js`.
3. Dynamic import of the shim resolves the re-export chain end-to-end (`shimModule.createDrawer` is a function).
4. The canonical ESM entry stays at `dist/index.js` (no `outExtension` rewrite).

---

## Impact

- **Affected surface**: every consumer that installs `@samline/drawer` via a symlink (`file:` protocol, pnpm, Yarn workspaces). Direct installs (`npm install` from the registry) are not affected because the package is copied, not symlinked.
- **Severity rationale**: the failure is total — the drawer entry fails to load, taking every dependent module down. There is no graceful degradation.
- **Detection**: the browser console shows a 404 on `dist/index.mjs`.
- **Workaround before the fix**: install the package without a symlink, or add a `dist/index.mjs` shim by hand.
