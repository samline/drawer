This page installs the exact beta.4 release and opens a working drawer. By the end you will have a per-id host, a controller, and the shared registry used by the root named exports.

## Prerequisites

- **Node.js 20+** when bundling (the package is published as ESM + CJS and ships TypeScript types).
- A package manager — `npm`, `pnpm`, `yarn` or `bun`.
- A runtime target of **ES2020** in the browser.

## First example

Drop this in any modern bundler or TypeScript project:

```ts title="drawer.ts"
import '@samline/drawer/styles.css'
import { createDrawer } from '@samline/drawer'

document.querySelector('#app-shell')?.setAttribute('data-drawer-wrapper', '')

const drawer = createDrawer({
  id: 'filters',
  triggerText: 'Open drawer',
  showHandle: true,
  direction: 'bottom',
  title: 'Drawer title',
  description: 'Drawer description',
  content: 'Drawer content'
})

drawer.setOpen(true)
```

What this does:

- Registers `filters` and creates its dedicated `<div data-drawer-vanilla-root="filters">` under `document.body`.
- Renders a built-in `<button data-drawer-vanilla-trigger>` because `triggerText` is set. The button stays mounted while the drawer is closed.
- Renders the built-in handle because `showHandle: true` is set.
- Mounts the overlay and dialog lazily when `setOpen(true)` runs.

On close, the overlay and dialog remain for the 500 ms exit transition and are then removed by a 600 ms safety timeout. The per-id host and optional trigger remain until `drawer.destroy()` or `destroyDrawer('filters')` runs.

The shared stylesheet provides motion behavior and the built-in handle, not a finished panel theme or directional positioning. Add your own styles through `overlayClassName`, `contentClassName`, or the selectors in the [CSS styling reference](/drawer/reference/css-styling/).

To mount inside a custom target, pass `container`. The old `mountElement` name remains available for compatibility but is deprecated; the target resolves as `container ?? mountElement ?? document.body`. Every id still receives its own host child inside that target.

## Browser global (no bundler)

If you do not have a bundler, load the separate beta.4 stylesheet and IIFE, then use the `window.Drawer` global:

```html title="index.html"
<div data-drawer-wrapper id="app-shell">
  <main>App shell</main>
</div>

<link rel="stylesheet" href="https://unpkg.com/@samline/drawer@3.0.0-beta.4/dist/style.css" />
<script src="https://unpkg.com/@samline/drawer@3.0.0-beta.4/dist/browser/global.global.js"></script>
<script>
  window.Drawer.createDrawer({
    id: 'filters',
    triggerText: 'Open drawer',
    showHandle: true,
    direction: 'bottom',
    title: 'Drawer title',
    content: 'Drawer content'
  })
</script>
```

:::caution[Pin the version in production]
Both URLs intentionally pin `@3.0.0-beta.4`. Keep the CSS and JS on the same exact version when upgrading.
:::

The IIFE is JavaScript only. It attaches `window.Drawer`; it does not inline CSS or inject a `<style>` element.

See the [Browser global reference](/drawer/reference/browser/) for the full surface, including `Drawer.createDrawer`, `Drawer.destroyDrawer`, and the browser bundle's registry lifecycle.

## Registry helpers (bundler)

Bundler users import the named helpers from the root entrypoint. There is no root `browser` singleton and importing the root package does not install `window.Drawer`:

```ts title="bundler.ts"
import { createDrawer, destroyDrawers, getDrawer, openDrawer } from '@samline/drawer'

createDrawer({ id: 'filters', title: 'Filters', content: 'Body' })
openDrawer('filters')
getDrawer('filters')?.setActiveSnapPoint(null)
destroyDrawers()
```

All root named helpers share one module-level registry. Use distinct `id` values for independent drawers. The standalone IIFE exposes an equivalent API over the registry owned by that loaded browser bundle; do not rely on separately bundled root and CDN copies sharing state.
